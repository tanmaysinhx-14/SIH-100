# DSAS Problem Statement and Boundaries

## Problem

An analyst monitoring many RF channels needs a fast way to identify which channels have unusual energy and which observations deserve attention first. A prototype should make the analysis pipeline visible without requiring specialized radio hardware.

## Proposed solution

DSAS simulates complex IQ data across multiple channels, measures channel energy with Welch PSD, classifies signal shapes with a lightweight Random Forest, ranks channels using an explainable priority formula, and presents the result in a Streamlit dashboard.

## Intended users

- A student or engineer learning the relationship between IQ data, PSD, features, and classification.
- A demo audience evaluating a software-defined spectrum-awareness concept.
- A developer who needs a hardware-independent pipeline before adding a future input adapter.

## In-scope MVP

- Four synthetic signal families: background noise, civilian broadcast, hostile radar, and hostile jammer.
- Ten channels by default, 1,024 IQ samples per channel, 1 MHz sample rate.
- Welch PSD measurement with a 256-sample segment.
- Threshold-based power excess and threat-weighted prioritization.
- Nine statistical/spectral features and a 100-tree Random Forest.
- Streamlit controls, KPI cards, charts, incident feed, I/Q waveform, and STFT inspector.
- In-memory state and optional local model save/load.

## Out of scope

- Live SDR hardware, antennas, drivers, or field RF collection.
- Real-world signal attribution, emitter geolocation, or electronic-warfare tasking.
- Deep neural networks, GPU training, or long-running optimization.
- Distributed sensors, authentication, multi-user permissions, and production database guarantees.

## Success criteria

The MVP is successful when a new user can install and run it, observe all four simulated classes, change the threshold, execute a sweep, inspect a waveform and spectrogram, understand why a channel is prioritized, and reproduce the verification checks from the documentation.

## Honest limitations

The model learns from synthetic distributions generated by the same project. This supports software testing and demonstration but does not establish performance on real RF data. Any future hardware or field-data effort must introduce new datasets, labeling rules, calibration, validation, and safety review.

## Next problem to solve

The immediate engineering problem is not adding hardware. It is making the current software pipeline trustworthy and teachable:

- prove behavior with automated tests;
- measure held-out classifier performance;
- make scores explainable;
- make incidents exportable and bounded;
- distinguish aggregate channel energy from frequency-bin PSD;
- preserve contracts as multiple contributors work in parallel.
